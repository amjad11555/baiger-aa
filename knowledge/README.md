## لماذا الفصل

فادي **لا يذكر سعراً ولا يمنح خصماً ولا يَعِد بضمان**. هذه قواعد مكتوبة في ملفه،
لكن القاعدة المكتوبة ليست ضماناً كافياً: **أي رقم يدخل سياق النموذج قابل للتسريب**،
ولو كان مكتوباً فوقه «ممنوع ذكره». الطريقة الوحيدة المضمونة أن يبقى خارج سياقه.

لذلك كل رقم وكل وعد تعاقدي في الملفين الداخليين، ويصل للفريق البشري في المكالمة.

**الملفات التي تدخل سياق الوكيل محدّدة في `KNOWLEDGE_FILES` داخل `src/prompt.js`.**
⛔ لا تُضِف الملفين الداخليين إلى تلك القائمة.

بعد أي تعديل: **أعد تشغيل الخادم** ليُعاد بناء الـ system prompt.

## فجوات بين الملفات والكود

`objections.md` يفرض تصنيفات ومتابعات لا يدعمها النظام بعد.
الحل المؤقت: تُكتب نصاً داخل `summary` بصيغة `[objection: no_need]`.

**للتطوير:**
1. حقل `objection_type` مستقل ليمكن الفلترة والمتابعة الآلية.
2. أداة `send_proof_pack` لإرسال نماذج الأعمال وأرقام العملاء أثناء المحادثة —
   مذكورة كقاعدة إلزامية وغير موجودة في `src/tools.js`.
3. جدولة متابعة تلقائية حسب نوع الاعتراض (3–5 أيام / 45 / 60–90 يوماً).

## ملاحظة على الحجم

الـ system prompt الحالي ~96 ألف حرف. مع prompt caching (يُبنى مرة عند الإقلاع)
التكلفة مقبولة، لكنها تزيد مع كل رسالة. إن صار بطيئاً أو مكلفاً، الحل تحميل
قسم الخدمة المطلوبة وملف الاعتراضات عند الحاجة عبر أداة، بدل تحميل كل شيء دائماً.
